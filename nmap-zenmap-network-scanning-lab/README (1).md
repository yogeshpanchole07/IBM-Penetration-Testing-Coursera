# Nmap GUI (Zenmap) — Network Scanning Lab

A documented hands-on lab using **Nmap and Zenmap** in the Skills Network cloud-based Windows environment. The repository includes a formal report and all **16 screenshots** in workflow order.

## Lab details

- **Lab:** Hands-on Lab: Scanning Network Environment with NMap
- **Date performed:** 12 October 2026
- **Environment:** Skills Network cloud-based Windows lab
- **Tool:** Nmap / Zenmap GUI (version displayed in screenshots: 7.991)
- **Goal:** Scan hosts by domain name or IP address and review scan profiles, port states, services, host details, and topology.

## Objectives

- Use Zenmap to run network scans.
- Compare Quick scan and Intense scan profiles.
- Identify open and filtered TCP ports.
- Review service/version detection, OS guesses, and traceroute output.
- Explore Zenmap's Ports/Hosts, Topology, and Host Details tabs.

## Lab workflow

1. Open the cloud Windows lab environment.
2. Download Nmap from the official [Nmap download page](https://nmap.org/download.html).
3. Install Nmap and the required Npcap component.
4. Launch Zenmap.
5. Run a Quick scan against `scanme.nmap.org`.
6. Run an Intense scan against `scanme.nmap.org`.
7. Review Ports/Hosts, Topology, and Host Details.
8. Scan `127.0.0.1` and `cloud.ibm.com` as shown in the lab screenshots.

## Commands represented by the Zenmap profiles

The screenshots show the following command forms generated by Zenmap:

```bash
nmap -T4 -F scanme.nmap.org
nmap -T4 -A -v scanme.nmap.org
nmap -T4 -F 127.0.0.1
nmap -T4 -F cloud.ibm.com
```

- `-T4` selects a faster timing template.
- `-F` scans a smaller set of commonly used ports.
- `-A` enables additional detection features such as OS detection, version detection, default scripts, and traceroute.
- `-v` increases output verbosity.

## Observed results

| Target | Port | State | Service / observation |
|---|---:|---|---|
| `scanme.nmap.org` | 22/tcp | Open | SSH; intense scan labeled it `tcpwrapped` |
| `scanme.nmap.org` | 25/tcp | Filtered | SMTP |
| `scanme.nmap.org` | 80/tcp | Open | HTTP; intense scan showed an Apache HTTP server fingerprint |
| `scanme.nmap.org` | 9929/tcp | Open | `nping-echo` in the intense scan |
| `127.0.0.1` | 135/tcp | Open | MSRPC |
| `127.0.0.1` | 445/tcp | Open | Microsoft-DS |
| `127.0.0.1` | 3389/tcp | Open | MS-WBT-Server / Remote Desktop-related service |
| `cloud.ibm.com` | 80/tcp | Open | HTTP |
| `cloud.ibm.com` | 443/tcp | Open | HTTPS |

**Note:** These are observations captured on the lab date, not permanent facts. DNS answers, filtering, services, and port states can change. OS and version fingerprints are estimates. The localhost scan describes the cloud lab machine.

## Port states at a glance

- **Open:** A service responded as accepting connections.
- **Closed:** The host was reachable, but no service was listening on the probed port.
- **Filtered:** Filtering or lack of response prevented Nmap from determining the state conclusively.

A port scan identifies network exposure; it does not prove that a service is vulnerable.
